# 다운스트림 실험 — 원문 vs 개선본을 실제 에이전트에 주고 비교

`run.py <라벨> [--tasks T1,T2,T3] [--conds raw,improved] [--improvers claude,codex] [--reps 1] [--max-turns 25]` : `fixture/`(todo-cli, Python 표준 라이브러리)를 임시 폴더에 복사해 Claude Code 헤드리스(`claude -p`, 설정 모델·effort)로 과제를 수행시키고 턴 수·토큰·비용·숨은 채점(`checks/check.py`)을 기록한다. 결과 `out/<라벨>.json`.
- 과제: T1 중복 할일 차단 / T2 완료 처리 / T3 내보내기(형식 미정 → 미명세 과제).
- 2026-10-07 파일럿(T1, 각 1회): 개선본 턴 19 vs 24, 입력 −30%, 비용 +11%, 둘 다 통과 → 쉬운 과제는 이득 없음. 미명세 과제 T2·T3 × 3회가 다음 실험(fable 사용량 소모, 관리자 승인 후).

- 측정 도구 오염 수정: 입력창 임시 파일을 작업 폴더 안에 만들어 개선기가 그 파일을 "먼저 읽을 파일"로 지목했다(첫 기준값 폐기, 임시 폴더로 이동).
- 한계: 과제 3개 × 1회라 잡음이 크다(같은 조건 T3 claude 가 통과·실패 모두 나옴). 판단을 굳히려면 --reps 3 이상.
