# 비교 벤치 품질 기준 (고정: 2026-10-09, 개선 전)

같은 입력(`cases.jsonl` 21건, 7유형 × 3)을 세 방식으로 처리해 비교한다.
- **(a) 개선 전 스킬**: 기준 커밋의 `pi-edit`·`instructions.md`·`ask.md` (`--ref` 로 지정, 필수)
- **(b) 개선 후 스킬**: 작업 트리의 같은 파일
- **(c) 일반 에이전트**: 같은 모델·effort 의 `claude -p` 에 "이 프롬프트를 개선해줘" + 원문. Claude Code 기본 시스템 프롬프트와 저장소 CLAUDE.md, 읽기 도구(Read·Glob·Grep)를 쓴다. 대화 지시어 유형은 같은 대화 2턴을 앞에 붙인다.

(a)·(b)는 실제 Ctrl+Q 경로 그대로 돈다(0토큰 게이트·질문 모드 포함). 질문 모드의 답은 "Enter = 전부 권장"으로 자동 수락한다(`PI_ASK_ANSWER=""`).

## 측정 항목
- 입력 토큰 = input + cache_creation + cache_read (호출 전부 합산: (a)·(b)는 1차 질문 + 2차 본문)
- 출력 토큰 = output_tokens 합산, 비용 = total_cost_usd 합산, 소요 = 벽시계 초
- 품질 점수 = 아래 5항목 × 0~2점 = 10점 만점

## 품질 5항목 (각 0~2점)
| 항목 | 채점 | 2점 | 1점 | 0점 |
|---|---|---|---|---|
| 의도 보존 | LLM | 원문의 과제·범위·명시 제약(금지·수치·이름)을 그대로 지키고 별개 기능을 덧붙이지 않음 | 사소한 범위 확장 또는 제약 1개 누락 | 다른 과제로 바뀌거나 명시 제약을 어김 |
| 사실 비왜곡 | LLM + 자동 | (원문에 사용자가 적은 과제·대상은 제외하고) 개선본이 새로 덧붙인 것 중 저장소·<프로젝트>·<대화>·원문에 없는 파일·스택·구조·수치를 사실로 쓰지 않음(모르는 것은 "확인할 것"·[가정]) | 근거 없는 전제 1개 | 지어낸 파일·스택을 사실처럼 2개 이상 |
| 질문 수 적정성 | 자동 | 질문 수가 케이스 기대 범위 `q` 안 | 범위에서 1개 벗어남 | 2개 이상 벗어남 |
| 길이·형식 준수 | 자동 | 줄 수 ≤ 상한, 바로 붙여넣기 가능(코드펜스·서문·맺음말 없음) | 상한의 1.5배 이하, 또는 형식 위반 1건 | 그 밖 |
| 실행 가능성 | LLM | 에이전트가 되묻지 않고 바로 착수 가능(먼저 볼 파일·단계·검증 방법이 구체적) | 착수는 가능하나 검증 기준이나 첫 단계가 흐림 | 무엇을 할지 불분명 |

### 자동 판정 세부
- **질문 수** = 1차 질문 단계에서 화면에 띄운 질문 수 + 출력 안의 `[확인 필요` 개수 + (`[확인 필요`가 없는 줄 중) `?`로 끝나는 줄 수.
- **사실 자동 상한**: 출력의 경로형 토큰(알려진 확장자로 끝나거나, `~/`·`./`·`/`로 시작하거나, 저장소 최상위 폴더명으로 시작하는 `a/b` 꼴 — `bcrypt/argon2` 같은 낱말 병기는 제외)이 저장소 파일(git ls-files 의 경로나 파일명)·원문·대화 어디에도 없고 같은 줄에 `[가정]`·`가정`·`확인`·`예:`·`e.g.` 표시도 없으면 지어낸 경로로 본다. 1개면 사실 점수 상한 1, 2개 이상이면 0.
- **줄 수 상한**(빈 줄 제외):
  - `brief`(원문이 "짧게"·"brief"로 시작): **10줄**
  - `short`(원문 8단어 이하, brief 아님): **14줄** — "짧은 입력에는 짧게"(관리자 2026-10-09 요청, 10-07 "짧은 요청도 상세 지침" 결정을 대체)
  - `structured`: 원문 줄 수 + 6줄
  - 그 밖: **22줄**
- **형식 위반**: 코드펜스(```), 첫 줄 서문("다음은"·"개선된 프롬프트"·"Here is"·"Improved prompt" 류), 마지막 줄 맺음말("필요하면"·"도움이"·"Let me know" 류), 본문 앞뒤 `---` 구분선. 위반 1건이면 길이 점수 −1(최저 0).

## LLM 심사
- 심사 모델은 개선 모델과 다른 `sonnet`, effort low. 출력 하나씩 **절대 평가**(어느 방식인지 모르게, 순서 무관).
- 출력마다 3회 심사해 항목별 평균(`--passes 3`, 2026-10-09 추가). 같은 글자의 출력이 6점·9점으로 갈린 심사관 편차를 줄이려는 측정 절차 보강이며 세 방식에 똑같이 적용한다. 항목 정의·점수는 고정 그대로.
- 심사관에게 주는 것: 원문, <프로젝트> 블록(실제 `project_ctx` 출력), 저장소 파일 목록(git ls-files), <대화>(있을 때), 수락된 권장 답(있을 때 — **권장안 자체에 지어낸 사실이 있으면 사실 비왜곡 감점**), 개선본.
- 수동 검토: 유형마다 1건 이상을 사람이(작업 에이전트가) 읽고 LLM 점수와 다르면 `RESULTS.md`에 적는다.
