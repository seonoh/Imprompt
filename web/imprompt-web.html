Imprompt

코딩 에이전트에 보낼 요청을 붙여 넣으면, 바로 착수할 수 있는 지침으로 다시 써 줍니다. 설치도 API 키도 필요 없습니다. 첫 실행 때 Claude 사용 동의 한 번만 누르면 됩니다.

개선된 프롬프트 예시 결과 
목표: 이 프로젝트에 로그인 기능을 구현한다.

요구사항
- 착수 전 확인(코드에서): 프레임워크·언어·DB·ORM, 기존 User 모델/인증 미들웨어/세션·토큰 처리 코드, 라우팅 규칙, 환경변수 관리 방식, 기존 테스트 구성과 실행 명령.
- 착수 전 질문(갈림길): 인증 방식(세션 쿠키 vs JWT vs 기존 라이브러리), 로그인 식별자(이메일 vs 아이디), 회원가입·로그아웃·비밀번호 재설정·소셜 로그인 포함 여부, 프론트 UI까지 만들지 API만 만들지.
- 로그인 엔드포인트: 식별자·비밀번호를 받아 사용자 조회 → 비밀번호 검증 → 인증 상태 발급(세션 또는 토큰) → 성공 응답.
- 비밀번호는 평문 저장·비교 금지, bcrypt/argon2 등 단방향 해시. 기존 해시 방식이 있으면 그것을 따를 것.
- 입력 검증: 필수값 누락·형식 오류 시 400 계열, 자격증명 불일치 시 사용자 존재 여부를 구분할 수 없는 동일한 메시지.
- 인증 상태 관리: 세션이면 로그인 시 세션 ID 재생성, 쿠키 HttpOnly·Secure·SameSite; JWT면 만료시간, 서명 키는 환경변수.
- 보호된 라우트의 인증 미들웨어가 없으면 추가, 있으면 재사용.
- 테스트: 성공 로그인, 잘못된 비밀번호, 존재하지 않는 사용자, 필수값 누락, 보호 라우트 접근 케이스.

제약·주의
- 기존 코딩 컨벤션·디렉터리 구조·에러 응답 형식을 따를 것.
- 비밀번호·토큰·세션 ID를 로그에 남기지 말 것. 비밀키는 환경변수로만.
- 요청 범위 밖의 기능(권한 관리, 프로필 등)은 추가하지 말 것.

완료 기준
- 유효한 자격증명으로 로그인하면 인증 상태가 발급되고 보호 라우트 접근이 허용된다.
- 잘못된 자격증명·누락 입력은 적절한 상태코드로 거부되며 사용자 존재 여부가 노출되지 않는다.
- 작성한 테스트와 기존 테스트가 프로젝트의 테스트 명령으로 통과한다.
사용량은 로그인한 본인 claude.ai 계정에서 차감됩니다. 같은 입력은 5분 동안 결과를 재사용합니다. 새로 받으려면 "다시 쓰기". 터미널(Claude Code·Codex)에서는 같은 규칙이 Ctrl+Q로 동작합니다.
